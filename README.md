# snakemake-sra-rnaseq

A reproducible Snakemake workflow that takes a public SRA study accession and returns a gene-level count matrix, QC report, and DESeq2 differential expression results.

Every dependency is pinned in per-rule conda environments, the sample sheet is generated by SQL against the SRA metadata tables in BigQuery rather than assembled by hand, and the DAG is dry-run tested in CI on every push.

```
SRA accession
   ↓  prefetch + fasterq-dump
FASTQ
   ↓  fastp (adapter/quality trimming) → FastQC
trimmed FASTQ
   ↓  salmon (selective alignment, decoy-aware index)
transcript quantifications
   ↓  tximport (lengthScaledTPM)
gene count matrix
   ↓  DESeq2 (+ apeglm LFC shrinkage)
results tables, MA plots, PCA, MultiQC report
   ↓  fgsea, WGCNA, region-matched eQTL, GWAS Catalog
convergence table + HTML report
```

## Quickstart

```bash
git clone https://github.com/masondandrus/snakemake-sra-rnaseq
cd snakemake-sra-rnaseq

# 1. Build the sample sheet from SRA metadata in BigQuery
python workflow/scripts/fetch_sra_metadata.py --study SRP123456 --audit
python workflow/scripts/fetch_sra_metadata.py --study SRP123456 --out config/samples.tsv

# 2. Point config/config.yaml at the right reference and set your contrasts

# 3. Check the plan, then run
snakemake -n
snakemake --use-conda --cores 16
```

Outputs land in `results/`: `counts/gene_counts.tsv`, `qc/multiqc_report.html`, `deseq2/*.results.tsv`, and diagnostic PCA/MA plots.

## Building the sample sheet with SQL

The SRA's metadata is queryable in BigQuery (`nih-sra-datastore.sra.metadata`), so run accessions, library layout, and submitter sample attributes can be pulled with a query instead of clicked out of the Run Selector. `resources/sra_metadata.sql` does this and normalises the result into the four columns the workflow requires: `run`, `sample`, `condition`, `library_layout`.

The catch worth knowing: sample attributes are submitter-defined key/value pairs, not fixed columns, so `treatment_sam` in one study is `condition_sam` or `genotype_sam` in the next. Run the audit query first — it lists every attribute key a study actually used, with example values — then edit the `COALESCE` block to match. Guessing here is how sample sheets end up quietly mislabelled, which is the kind of error that survives all the way to a volcano plot.

```bash
python workflow/scripts/fetch_sra_metadata.py --study SRP123456 --audit
```

## LLM-assisted sample sheet curation (optional)

`workflow/scripts/curate_samples.py` uses the Claude API to propose `condition`
assignments from submitter free text — the cases the SQL `COALESCE` block cannot
reach, like a design written as "5 mg/kg cocaine, 24h withdrawal" inside
`source_name_sam`.

**It is deliberately not a Snakemake rule.** Model output is non-deterministic;
a model call inside the DAG would mean the same accession could yield different
counts on different days, which destroys the property this repo exists to
demonstrate. The script writes a proposal and a provenance record, you review
and accept, and the committed `samples.tsv` is what the pipeline reads. Every
number downstream traces to a reviewed, version-controlled artifact.

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # https://platform.claude.com

python workflow/scripts/fetch_sra_metadata.py \
    --study SRP123456 --dump-attributes resources/SRP123456.attributes.json

python workflow/scripts/curate_samples.py \
    --attributes resources/SRP123456.attributes.json          # one model call; writes a proposal
python workflow/scripts/curate_samples.py \
    --attributes resources/SRP123456.attributes.json \
    --accept --out config/samples.curated.tsv                 # no model call; writes a new sheet
```

`--accept` reads the saved proposal file. It never contacts the model, so the
labels that reach the sample sheet are the labels that were reviewed. It stops
if the attributes changed after the proposal, if any run is still `UNRESOLVED`,
or if `--out` already exists, and it leaves the input sample sheet untouched.
To overrule a label, edit its `condition` in the proposal and set its
`confidence` to `manual`; the acceptance record notes that the proposal was
edited.

The model is treated as untrusted input, not an authority. Responses are
rejected if they invent runs, drop runs, duplicate runs, or assign a condition
without quoting the attribute text it came from. The quote must sit in the
attribute that the response names, and it must not also occur under that
attribute in a run given a different label. These checks cannot catch two
labels that are swapped, which is why a person reviews the proposal. Anything the model cannot
support is returned as `UNRESOLVED` for you to resolve by hand rather than
guessed. Runs below high confidence are flagged in the report. Candidate
covariates — batch, sex, collection date — are surfaced as suggestions for
`deseq2.design`; the script never edits the design itself.

Each run writes `*.curation_provenance.json` recording the model, temperature,
prompt hash, input hash, token usage, and the raw response. Commit it next to
the sample sheet.

Cost is a few cents per study at current API rates.

## Design decisions

**Selective alignment with a decoy-aware index.** Salmon's decoy-aware selective alignment reduces spurious mappings from unannotated genomic sequence, which otherwise inflate abundance for a subset of transcripts (Srivastava et al., 2020). The cost is a genome-sized index build; the benefit is quantification that holds up on experimental rather than simulated data.

**`countsFromAbundance = "lengthScaledTPM"`.** Corrects for differences in average transcript length across samples while producing values on a count scale, so DESeq2's negative binomial assumptions still hold.

**prefetch before fasterq-dump.** Streaming `fasterq-dump` directly against NCBI is the usual cause of silently truncated FASTQ files on large studies. `prefetch` is resumable, and the rule carries `retries: 3`.

**Layout-aware rule pairs rather than a checkpoint.** Paired- and single-end runs are handled by separate rules with distinct output patterns, so the DAG resolves statically from the sample sheet. Mixed-layout studies work without special handling.

**Intermediate FASTQs are `temp()`.** Raw and trimmed reads are deleted once consumed. A 40-sample study stays in the tens of GB rather than hundreds.

**Per-rule conda environments.** Each rule declares its own pinned environment (`workflow/envs/`), so the salmon and R toolchains never have to co-resolve. Versions are pinned to the minor release.

## Multi-evidence convergence

A DESeq2 result gives you a ranked list and nowhere obvious to start. The
optional annotation module narrows it by asking which genes are named by more
than one kind of evidence: differential expression, hub status in a
co-expression module associated with the contrast, a cis-eQTL in the matched
tissue, and mapping to a GWAS variant for a relevant trait. Module association
is fitted on the module eigengenes with the DESeq2 design formula and the same
numerator and denominator as the contrast, and corrected across modules.

The axes are declared in config rather than hardcoded, and normalised to a
common contract, so a fifth line of evidence — differential ATAC peaks, CUT&RUN
targets, a druggable-genome list — is a config entry rather than a code change.
The same type can appear more than once; two brain regions is two eQTL axes.

Output is one row per gene with an `evidence` string (`DEG|eQTL|GWAS`), the
supporting statistic from each axis, and an UpSet plot of the intersections.

eQTLs come from GTEx by default; RatGTEx is a one-line switch and covers the
regions the addiction literature actually uses (NAcc, IL, PL, OFC, LHb, pVTA,
RMTg, BLA). GWAS comes from the NHGRI-EBI Catalog. Both are cached under
`resources/annotation/` with a provenance record of source URL, retrieval date,
and thresholds.

Two things the module is careful about. WGCNA is unreliable below roughly 15
samples, so under `annotation.wgcna.min_samples` the rule writes an empty hub
table and records why, and convergence reports how many axes it actually had —
a missing axis is honest, a fabricated one is not. And the evidence count is a
prioritisation heuristic, not a statistic: the axes are correlated, and eQTL
and GWAS naming the same gene is shared gene identity, not colocalisation.

Details and configuration in [docs/convergence.md](docs/convergence.md).

## Validation

The full workflow was run from raw SRA downloads on GSE42805 ([Feng et al. 2014](https://pubmed.ncbi.nlm.nih.gov/24758366/);
chronic cocaine vs. saline, mouse nucleus accumbens, 3 vs. 3, single-end) on two
machines: a laptop in July 2026 and a clean desktop install in November 2026
(commit `e8240f2`, Snakemake 9.27.1, WSL2 Ubuntu 26.04, 28 cores).

| | Laptop, July 2026 | Clean desktop, November 2026 |
|---|---|---|
| Salmon mapping rate | 81–85% | 81.4–85.4% |
| Genes retained after filtering | 24,297 | 24,295 |
| Genes at padj < 0.05 | 27 | 26 |
| Gene sets at padj < 0.05 (fgsea) | 18 | 14 |

The differential expression result reproduces to within one gene. The fgsea
count moves more because fgsea is permutation-based and `msigdbr` is not
version-pinned.

What this run does and does not show:

- **It is a test that the workflow runs end to end and reproduces.** It is not a
  re-analysis of the paper. The contrast is weak: the samples do not separate by
  condition on PCA, and 26 genes pass the threshold.
- **WGCNA did not run.** Six samples is below `annotation.wgcna.min_samples`
  (15), so the rule wrote an empty hub table and the convergence table reports
  three axes available, not four. The WGCNA rule has not yet produced modules on
  a public dataset.
- **The convergence table is uninformative here.** 8 of 26 DE genes have a
  human-ortholog cis-eQTL in GTEx nucleus accumbens, but that eQTL list covers
  12,026 genes, so 8 of 26 is about what chance gives. None of the 9 genes
  mapped to genome-wide significant cocaine dependence or cocaine use disorder
  associations in the GWAS Catalog is differentially expressed.
- **The enrichment result is reported, not interpreted.** The significant GO:BP
  sets are sensory and cardiac terms, which is not a credible nucleus accumbens
  signal at this sample size.

The clean install found five defects that the development machine had hidden: an
`r-wgcna` version pin that no longer resolved, the retirement of GWAS Catalog
REST API v1 (the fetch script now uses v2), two wrong EFO trait identifiers in
the default config, a null-default operator missing in R 4.3, and a report rule
that silently dropped the enrichment plot. All five are fixed in the commits
leading to `e8240f2`.

A larger study (15 or more samples, paired-end) is the next validation target,
so that the WGCNA and convergence steps run on data that can support them.

## Repository layout

```
config/
  config.yaml            reference URLs, tool parameters, design, contrasts
  samples.tsv            one row per SRA run
workflow/
  Snakefile              config parsing, input helpers, targets
  rules/                 download, qc, quant, de
  envs/                  pinned conda environments, one per toolchain
  scripts/               tx2gene.py, tximport.R, deseq2_init.R, deseq2_results.R
                         fetch_sra_metadata.py, curate_samples.py
resources/
  sra_metadata.sql       BigQuery sample-sheet query + attribute audit query
.github/workflows/ci.yml lint + dry-run on every push
```

## Configuration

| Key | Purpose |
| --- | --- |
| `reference.transcriptome_url` / `genome_url` | GENCODE FASTAs. Swap both together — the decoy index needs a matching genome build. |
| `salmon.kmer` | 31 by default; drop to 23–25 for reads under ~50 bp. |
| `salmon.libtype` | `A` infers strandedness; verify against `lib_format_counts.json`. |
| `deseq2.design` | Any DESeq2 formula over columns present in the sample sheet. |
| `deseq2.min_count` / `min_samples` | Pre-filtering threshold, independent of the design. |
| `contrasts` | `[factor, numerator, denominator]` per contrast; the key becomes the output filename. |

Non-human studies need the transcriptome and genome URLs changed. `tx2gene.py` parses GENCODE-style pipe-delimited FASTA headers; an Ensembl FASTA needs a GTF-derived map instead.

## Running on a cluster

```bash
snakemake --use-conda --profile <your-profile> --jobs 100
```

Rules declare `threads` and `mem_mb`. The salmon index build is the memory ceiling at roughly 32 GB for a decoy-aware human index.

## Testing

CI runs `snakemake --lint`, a full dry run against `.test/config.yaml`, a static check of the Python scripts, and the Python unit tests on every push. Run the same checks locally:

```bash
snakemake --lint
snakemake -n --configfile .test/config.yaml
python -m pytest tests/unit
```

Two further layers need R with DESeq2, tximport and WGCNA, and CI does not run them yet:

```bash
Rscript tests/unit/run_r_tests.R .        # results table, enrichment ranking, module-trait model
python -m pytest tests/integration        # salmon output to convergence table on synthetic data
```

The integration test simulates salmon output with known structure: one module driven by treatment, one driven by sex, one driven by neither, a gene with a p-value of zero, and a count outlier. It then checks that every modeled gene reaches the results table, and that the hub axis of each contrast holds genes from the module tied to that contrast and none from the others.
